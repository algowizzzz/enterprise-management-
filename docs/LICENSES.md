# Third-party licences

The inventory below is generated by `scripts/license_report.py` from the
metadata of every installed dependency. Regenerate it whenever the dependency
set changes.

**This is an inventory, not legal advice.** Whether a licence is acceptable is a
decision for your own review. This document exists so that review has something
accurate to work from, rather than starting with a dependency tree and a
spreadsheet.

---

## The short version

**The framework is MIT.** Verified from its own `LICENSE` file — a copy is at
[`LICENSE-frappe.txt`](LICENSE-frappe.txt) — not from its
package metadata, which declares nothing — worth knowing, because an automated
scanner will report it as unlicensed and that will look alarming until someone
opens the file.

**Nothing in the dependency set is AGPL**, and nothing is GPL. The strongest
licences present are LGPL and MPL, on a handful of libraries used as libraries.

**The GPL-licensed build tool is not here.** The framework's usual command-line
tool is GPL-3.0; this project replaces it with its own, so that dependency does
not exist. It is neither installed nor shipped.

**Our own code is MIT**, declared in package metadata so a scanner sees it.

## The distinction that matters most

Copyleft obligations — GPL, LGPL, MPL — attach when software is **distributed**.
Running software inside your own organisation, on your own servers, for your own
employees, is generally not distribution, which is why internal deployment is
the least constrained case for this kind of dependency set.

The licence that does not work that way is **AGPL**, which treats use over a
network as distribution. There is no AGPL here, and the check that proves it is
in the report below.

Two things would change this analysis, and both are worth flagging before they
happen rather than after:

1. **Distributing the software outside the organisation** — to a subsidiary that
   is a separate legal entity, to a client, or as a product. LGPL and MPL
   obligations would then attach, and they are satisfiable but not free: they
   require offering the corresponding source of those components and keeping
   them replaceable.
2. **Modifying an LGPL or MPL component** rather than using it as published. The
   obligations attach to the modified files.

Neither applies to installing and running this internally. Both should be raised
with your own review if either becomes the plan.

## What was removed, and why

A geo-IP package that the framework uses to guess a country from an IP address
was removed from the dependency set. Its Python wrapper is BSD-licensed, but it
embeds a 2018 snapshot of a database whose upstream terms changed the following
year. The framework wraps that import in a try/except and returns nothing when
it is absent, so the feature degrades and nothing else does — the full test
suite passes without it. Explaining the data licence to a review team, for a
feature this product does not use, costs more than the feature is worth.
