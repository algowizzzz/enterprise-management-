# Glossary

Plain-English meanings of the words you'll see in the platform. Words in
**bold** in a definition have their own entry.

| Term | What it means |
|---|---|
| **Action plan** | The steps agreed to fix an **escalation**, with an owner, a start date and a due date. |
| **Annual review** | Once a year, a **forum's** owner confirms the forum still meets its **mandate**, its compliance contact counter-signs, and a compliance reviewer records the result. |
| **Approval chain** | All the approval steps a **policy** version needs. It is *complete* when every step has been decided with no objection. |
| **Approval route** | The list of people who must approve a request or a policy, and in what order. Your administrator sets it up. |
| **Approval step** | One person's (or one role's) decision in an **approval chain**. |
| **Attestation** | Confirming that a record is accurate, or saying where it is not. |
| **Attestation campaign** | A round of **attestations** sent to many people at once, for example the annual forum inventory attestation. |
| **Audience** | The people a published **policy** is sent to. |
| **Breached** | An **escalation** that has gone past its **time limit**. |
| **Bypass** | A recorded decision to skip one **approval step**, with a written justification. Only certain senior roles can authorise one. |
| **Charter** | A **forum's** founding document: its purpose, membership, powers and reporting lines. It has versions and is **challenged** by the governance office. |
| **Challenge** | The governance office's check of a **charter**: *Cleared*, *Changes Requested* or *Not Reviewed*. |
| **Classification (of a change)** | Whether a change to a **policy** is *Major* or *Minor*, worked out from a short set of questions. It decides who approves. |
| **Closure** | How an **escalation** ended (for example *Resolved* or *Risk Accepted*), recorded against agreed criteria before the matter is closed. |
| **Committee** | See **forum**. |
| **Compliance review** | A decision about whether a **forum** is properly set up: *Compliant*, *Non-Compliant*, *Not Applicable* or *Returned To Creator*. |
| **Compliance standing** | Where a **forum** stands after its latest **compliance review**. *Pending* means it is waiting for one and is **locked**. |
| **Counter-sign** | The second signature on a **dual-signature** **attestation**. |
| **Coverage** | Whether each risk category is looked after by a **forum** or a **policy**, for each part of the organisation. |
| **Delegate** | Someone allowed to act for you for a period, for example while you are on leave. |
| **Disband** | To take a **forum** out of service. Nothing is deleted; its history stays readable. |
| **Doc AI** | Your organisation's document editor. **Open in Doc AI** hands a policy over to it, if your administrator has connected it. |
| **Dual signature** | An **attestation** that needs two people: one answers, the other **counter-signs**. |
| **Escalation** | A matter that needs attention at a higher level: an incident, a limit breach, a regulatory matter, a policy breach and so on. |
| **Escalation register** | The list of every **escalation** you may see. |
| **Evidence pack** | A single downloadable file with a record, its history, approvals and attachments, for an auditor or regulator. |
| **Exception** | A written, approved permission to go ahead even though a rule (a **gate**) would stop you. |
| **Formation request** | A request to create a new **forum**, change one or retire one. |
| **Forum** | A governance body: a board, committee, council or working group. |
| **Forum inventory** | The list of every **forum**, with its standing. |
| **Forum map** | A picture of how **forums** report to each other. |
| **Gate** | A rule that must be met before a **policy** moves on, for example "a publication must be recorded before implementation". |
| **Horizon scanning** | Looking out for coming regulatory and other changes that may affect a **policy**. |
| **Impact** | What a change to a **policy** would reach: the people, **forums**, regulations and other documents linked to it. |
| **In force** | A **policy** that has been published and applies. |
| **Insights** | The reporting and analysis screens. |
| **Lifecycle** | The stages a **policy** passes through: Draft, Review, Approved, Published, Implemented and Retired. |
| **Locked** | A **forum** that cannot be edited until its **compliance review** is recorded. |
| **Mandate** | What a **forum** is responsible for. |
| **Matter** | See **escalation**. |
| **Minutes** | The written record of a **meeting**. Corrections add a new version; earlier versions are kept. |
| **Meeting** (sitting) | One gathering of a **forum**. |
| **Motion** | A proposal put to a **forum** for a vote. |
| **My work** | Your personal list of everything waiting on you. |
| **Owner** | The person accountable for a record, such as a policy owner or a forum owner. |
| **Pathway** | The **forums** an **escalation** goes to, and whether each must decide, oversee or simply be informed. |
| **Phase** | The stage of a **policy's** **lifecycle**. |
| **Policy** | Any governing document: a framework, policy, standard, procedure or guideline. |
| **Policy library** | The list of every **policy** you may see. |
| **Queue** | A group of people (a role or a team) an **escalation** waits with until one of them **takes ownership**. |
| **Quorum** | The minimum participation a **forum** needs for its decisions to count. |
| **Record history** | Everything that has happened to a record: changes, comments, attachments and notifications. |
| **Reference lists** | The lists the platform's drop-downs choose from, such as risk categories or organisation units. |
| **Regulatory requirement** | An obligation, from a law or a regulator, that **policies** and **forums** can cite. |
| **Risk acceptance** | A formal decision to live with a risk rather than fix it, for a set period. It needs approval. |
| **Second line** | The independent risk and compliance functions that **challenge** the first line's work. |
| **Seat** | A place on a **forum**, held by a person or by a position (for example "Chief Risk Officer"). Seats are ended, never deleted. |
| **Sensitive** | An **escalation** with restricted handling. Only the people named on it and cleared staff can see it. |
| **Severity** | How serious an **escalation** is: High, Medium or Low. |
| **Systemic** | An **escalation** whose cause is shared, not a one-off. |
| **Take ownership** | Become the person responsible for an **escalation** waiting in a **queue**. |
| **Time limit** | How long an **escalation** may take before it is **breached**. |
| **Version** | One saved text of a **policy** or **charter**. New versions are added; nothing is overwritten. |
| **Violation** | A breach of a **policy**, logged and followed up. |
| **Watched details** | Details of a **forum** (such as its mandate or chair) that, when changed, send it back for a **compliance review**. |
